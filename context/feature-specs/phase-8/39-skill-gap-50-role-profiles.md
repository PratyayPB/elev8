# Skill Gap Engine — 50 Canonical Role Profiles

## Objective

Add 50 high-demand/popular career roles and their canonical top skill requirements to the existing deterministic `SkillGapService`.

The Skill Gap Engine must remain **100% deterministic and zero-LLM**.

The canonical role data is a baseline for role normalization and skill-gap calculation. It is not intended to represent every skill in every job posting.

Current labor-market evidence supports strong demand/growth across software development, AI/ML, data, cybersecurity, cloud/DevOps, product/design and related technology roles. The World Economic Forum's Future of Jobs 2025 lists Big Data Specialists, FinTech Engineers, AI and Machine Learning Specialists, Software and Applications Developers, Security Management Specialists, Information Security Analysts and DevOps Engineers among important/faster-growing roles. citeturn0search2turn0search50

The U.S. Bureau of Labor Statistics' current 2024–2034 projections show particularly strong growth for Data Scientists (33.5%), Information Security Analysts (28.5%) and Software Developers (15.8%). citeturn0search0turn0search1

O*NET/Lightcast 2025 employer-posting data for Software Developers shows strong demand for Python, AWS, Java, SQL, JavaScript, Azure, Kubernetes, Git, REST APIs, React, Docker and related technologies. citeturn0search3

# 2. Experience-Level Profiles

For **every one of the 50 roles**, create:

```text
ENTRY
JUNIOR
MID
SENIOR
LEAD
```

This produces:

```text
50 roles × 5 levels = 250 RoleSkillProfile records
```

Each profile must contain at least five `RoleSkillRequirement` records.

Minimum:

```text
250 × 5 = 1,250 RoleSkillRequirement records
```

More requirements may be added where necessary.

---

# 3. Proficiency Model

Use the existing five-level proficiency enum:

```text
BEGINNER = 1
BASIC = 2
INTERMEDIATE = 3
ADVANCED = 4
EXPERT = 5
```

Recommended progression:

```text
ENTRY
BEGINNER → BASIC

JUNIOR
BASIC → INTERMEDIATE

MID
INTERMEDIATE

SENIOR
ADVANCED

LEAD
ADVANCED → EXPERT
```

This is guidance, not a rule that every requirement must have the same level.

Role-specific skills should receive appropriate minimum proficiency.

---

# 4. Importance Model

Use the existing:

```text
CORE = 3
IMPORTANT = 2
SUPPORTING = 1
```

Recommended distribution:

```text
2–4 CORE
2–4 IMPORTANT
0–3 SUPPORTING
```

Do not mark every skill as CORE.

The purpose of importance is to make the deterministic gap engine prioritize genuine bottlenecks.

---

# 5. Estimated Learning Hours

Populate the existing `estimatedHours` field.

```text
Foundational skills: 10–30 hours
Intermediate skills: 30–80 hours
Advanced skills: 60–150 hours
Complex/specialized skills: 80–200+ hours
```

These values are estimates for gap-prioritization purposes and are not guarantees.

# 6. Skill Normalization

Before inserting requirements, map each skill to the application's canonical normalized skill representation.

Do not create duplicate skills for aliases.

Examples:

```text
JS
Java Script
JavaScript
→ javascript
```

```text
K8s
Kubernetes
→ kubernetes
```

```text
Amazon Web Services
AWS
→ aws
```

Where a supplied requirement combines multiple skills, split it into individual canonical skills if the existing schema models skills individually.

For example:

```text
AWS / Azure / GCP
```

should become separate requirements:

```text
aws
azure
gcp
```

Do not store slash-separated combined values as a canonical skill.

# 8. Database Seeding

Create/update an idempotent seed for the canonical role profiles.

The seed must:

1. Insert the 50 canonical roles.
2. Create five experience-level profiles per role.
3. Insert at least five skill requirements per role/level.
4. Set minimum proficiency.
5. Set importance.
6. Set estimated learning hours.
7. Avoid duplicate role profiles.
8. Avoid duplicate requirements.
9. Preserve existing compatible data.
10. Use canonical normalized role and skill identifiers.

Running the seed repeatedly must produce the same logical database state.

# 10. Data Quality Principle

These profiles are **canonical baselines**, not exhaustive job descriptions.

Do not turn every currently popular technology into a mandatory skill.

For example, a Backend Developer should not automatically require every one of:

```text
AWS
Azure
GCP
Kubernetes
Kafka
Redis
MongoDB
PostgreSQL
MySQL
```

The canonical profile should represent the role's core competencies.

Specific job requirements should be handled separately by job-description analysis and should not corrupt the canonical role baseline.

This distinction is important because an overly broad canonical profile would produce false-positive skill gaps.
